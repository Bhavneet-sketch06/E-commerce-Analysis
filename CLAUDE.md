# Personalised Offer Engine (Hackathon 2)

Decides which offer each customer of "Parvaaz Bazaar" (a fictional Punjab e-commerce platform) should get,
lets Claude choose and personalise it within business rules, validates every AI choice, and delivers offers
to classmates through a Telegram bot. A "mission control" dashboard lets marketers edit rules and see results.
Individual project, Punjab Jobs AI Bootcamp × J-PAL South Asia. Deadline Tue 27 Oct 2026, 12:00.

## Stack
- Node 20+ ESM, no TypeScript. `grammy` (bot), `@anthropic-ai/sdk` (model from `ANTHROPIC_MODEL`, default `claude-opus-5-5`),
  `express` (API + SSE), `dotenv`, `vitest`.
- Storage: one JSON file (`DB_PATH`, default `./data/offers.db.json`) via `src/db.js`. No native modules
  (better-sqlite3 fails to build on Windows/Node 20; don't reintroduce it).
- Dashboard: `dashboard/` (React + Vite + Tailwind v4 + recharts + framer-motion + lucide-react), built to
  `dashboard/dist` and served by Express.

## Commands
```bash
npm install
npm test           # vitest: validator, eligibility, data realism
npm run realism    # prints data realism stats (revenue concentration, seasonality, quadrants)
npm run dryrun     # runs the engine over synthetic customers, prints decisions + violations
npm run dev        # bot + API with --watch
```

## Pipeline (src/)
1. `data/generate.js` seeded synthetic customers (archetypes drive behaviour; `_archetype` is hidden ground truth,
   **never read it in the engine**), `generateForTelegramUser` builds a classmate's profile from onboarding answers.
2. `features.js` observed behaviour -> RFM, segment, churn risk, cart, points; `signals()` = plain-language reasons.
3. `uplift.js` pBase / pOffer / uplift -> quadrant (persuadable, sure_thing, lost_cause, do_not_disturb).
4. `rules/defaultRules.js` the business limits; `rules/eligibility.js` (PURE) contact blockers + allowed offers with ranges;
   `rules/validator.js` (PURE) checks a proposal: eligibility, ranges, budget, and that the message text promises
   nothing beyond the offer (%, ₹, points, free delivery, invented codes; Devanagari/Gurmukhi digits normalised).
5. `agent/agent.js` Claude proposes one offer (tool use), validator checks, one retry with violations, then deterministic fallback.
6. `engine.js` orchestrates, applies the control group, logs every decision, issues coupon codes.

## Conventions
- eligibility/validator/features/uplift stay pure (no I/O, `now` passed in) and fully tested. Any new rule needs a test.
- Coupon codes and expiry are generated by the system, never by the AI.
- Money is whole rupees (₹). Times are stored as ISO UTC; quiet hours and dates are evaluated in IST.
- Secrets only in `.env` (gitignored). Never print or commit tokens.
- Small steps; run `npm test` before every commit.
